# AI Radar website

Static site for the @ai_radar_ X account, served by GitHub Pages at https://airadar08.github.io (pushes to `main` go live in ~1 minute; no build step).

## Structure
- `assets/site.css` — shared tokens, header, buttons, resource cards, footer, reveal animation. Every page links it.
- `assets/site.js` — header border on scroll + scroll reveal (content stays visible without JS).
- `assets/hero.js` — flat 2D radar (plain canvas, no libraries) filling the home hero (`#radar`): rings and a sweep beam spreading up from the hero's bottom centre; coloured blips (8 slot colours) light up as the beam passes, and some show a name tag (AI lab names, AI NEWS / UPDATES / AI FACTS). Blips are placed only outside the hero copy and phones, re-laid out on resize.
- `assets/music.js` — background music on every site page (not the app): an original ambient loop made live with the Web Audio API (soft pad over four chords plus an echoing "radar ping"; no audio file). Browsers block sound until the visitor interacts, so it starts on their first click/tap/key press unless they paused it before (localStorage `airadar-music` = `off`). A round play/pause button is inserted just before "Follow on X" in the top bar; the music fades out while the tab is hidden. Loaded after `chat.js` on every page (and in `tools/pack_template.html`).
- `assets/logo.svg` — the AI Radar logo used on the X profile (mint circle, white "ai", radar arcs); also the favicon. Same SVG is inlined in each page header.
- `index.html` — home landing page (self-contained CSS/JS, does NOT link site.css or site.js): intro loader `#intro` (once per visit via sessionStorage `air-intro`; skipped with reduced motion or in a background tab; a full-screen canvas: a small radar whose sweep lights five card-colour blips, green last, locks on the green, glides it to the centre, then opens an even mint ring with sonar ripples onto the page, ~5.4 s; a safety timer always removes it; the hero entrance timers are offset by `window.__airIntro`), sky hero with two phones (left = real X profile screenshot `assets/img/x-profile.jpg`, right = chatbot mock), glass nav with letter-roll hover, custom cursor dot, progressive blur at top/bottom, "How it works" cross-fade carousel, AI labs ring (names only, no logos): full ring orbiting the copy on screens 800px+, sized so every circle stays on screen, turning with scroll plus a slow drift; a looping scrolling row on phones, "What you get" bento, `#repos-strip` (4 newest from `data/repos.json`), `#resources` grid of cheatsheet/prompt-pack cards, FAQ accordion, sky CTA with #stayontheradar, giant wordmark footer. Fonts: Instrument Serif (headings) + Inter. The `<!-- new-pack:home -->` and `<!-- new-cheatsheet:home -->` markers live in the `#resources` grid; cards use the same `.res` markup as before.
- `get-app/index.html` — the app's landing page (where every "Get app" button goes). Built from the home page's own system: same tokens and CSS (copied from `index.html`), same intro loader (shares sessionStorage `air-intro`, so it plays once per visit across both pages), hero radar (`assets/hero.js`, needs `#radar`, `.hero-copy`, `.phone-stage`), blur-in words, letter-roll buttons, two tilted phones with real app screenshots (`get-app/img/*.jpg`, 585x1266) that rise and drift on scroll, a "Best for you" 4-step cross-fade carousel, a "Every screen" phone gallery (`#screens`: Chat, Explore, Best for you, Saved, Glossary in phone frames, staggered on desktop, a swipe strip on phones that opens centred on Best for you), bento of features with real screens, install steps for Android/iPhone/computer with a copy-link box, FAQ, sweeping sky CTA and wordmark footer. Buttons open `app-beta/`. When the app moves to `app/`, update the links here. Retake screenshots when the app's look changes.
- "Get app": home nav has a glass `.getapp` pill (in `.nav-right`, next to "Follow on X"; on phones under 480px "Follow on X" hides and Get app stays) and an "App" footer column; inner pages (repos, cheatsheets, prompts, prompt-packs and every pack page, plus `tools/pack_template.html`) have `<a class="getapp">` in the header, styled in `assets/site.css` (under 440px "Follow on X" hides). `.getapp` is deliberately not `.btn`, so `assets/music.js` keeps its play button next to "Follow on X" (it picks the first `a.btn` in the bar).
- `prompts/index.html` — first prompt pack (50 AI prompts; data in the `PACK` array). Kept at this URL because it was shared on X.
- `prompt-packs/index.html` — Prompt packs listing, renders from `data/packs.json`. New packs live at `prompt-packs/<slug>/` (built by `tools/make_pack.py`).
- `cheatsheets/index.html` — gallery of posted cheatsheets; images in `cheatsheets/img/*.jpg` (1080x1350), each card has an `id` anchor linked from the home page.
- Home chips: "Daily AI news" and "AI facts" link to https://x.com/ai_radar_; "Cheatsheets" to `cheatsheets/`; "Free resources" to `#resources`.
- `assets/chat.js` — "Ask AI Radar" chat overlay on every page (reads the page's CSS tokens; the home page defines aliases for them). Answer order: (1) matching AI Radar resources first, found client-side from `data/repos.json`, `data/packs.json` and the `cheatsheets/` page; (2) for repo questions, a live GitHub search from the browser, no Worker call: `ghTerms` drops intent words (create, provide, good, want…) and joins phrases ("front end" → frontend); software topics (frontend, website, UI, backend…) search GitHub topics for the most-starred, still-active repos plus up to 3 new AI repos for that topic; AI topics (audio, agents, RAG…) get AI repos; "trending/new/latest" means repos created in the last 180 days. The same `ghTerms` cleaning matches our own resources. The app (`app-beta/app.js`) uses the same search code; (3) otherwise the Worker's AI answer with news headlines. Chat sessions: each visitor's history lives in their own browser tab (`sessionStorage` `air-chat-v2`; the app uses `localStorage` `airadar-chat-v1`); after 5 minutes without a message the next question starts a new session (a "New conversation" divider), and the AI gets only the current session, up to 12 messages (`SESSION_MS`, `CTX_MAX`; the Worker's `MAX_TURNS` is 12). `window.AIRadarChat.open()` and any `[data-open-chat]` element open it. Hidden until `ENDPOINT` is set.
- `worker/worker.js` — Cloudflare Worker (deployed separately on Cloudflare, not by GitHub Pages) that calls OpenRouter. Also answers `{action:"best", query, radar}` for the app's agentic "Best for you" search (`best()`): AI plans up to 2 queries per source (`PLAN_SYS`), the Worker searches GitHub, Hugging Face models/apps/datasets, HF papers and Hacker News, drops forks, archived repos, repos untouched for 2 years, duplicates (an AI Radar pick merges with the same GitHub repo) and articles when the user wants free, keeps the top 7 per kind, then AI picks 3–5 with why / trade-off / start (`RANK_SYS`; invented ids dropped); falls back to keywords and popularity when the AI fails; 4 per minute per IP; optional secret `GITHUB_TOKEN` raises GitHub's search limit. The OpenRouter key is a Cloudflare secret `OPENROUTER_API_KEY`; optional vars `MODEL` (default the free `nvidia/nemotron-3.5-super-vl:free`), `ALLOWED_ORIGIN`. Origin-locked, rate-limited, web search only for news-type questions. Also answers `{action:"preview", url}` (page title/description/site, no AI call) for the app's Add sheet; redeploy the Worker on Cloudflare after changing it.
- `repos/index.html` — Repos page; renders from `data/repos.json` (newest first). Home shows the 4 newest in the hidden-until-filled `#repos-strip`. Card images in `repos/img/`.
- `data/repos.json` — featured repos, written by `tools/update_site.py repo`.
- `tools/` — renderers (`render_cheatsheet.py`, `render_repo.py`), `post_x.js` browser snippet, `update_site.py`. Used by the scheduled posting task.
- `data/posts.json` — the archive of EVERY @ai_radar_ post (news, AI facts, repos, cheatsheets, prompt packs), newest first; schema in `tools/posts.py`. `update_site.py cheatsheet|repo` and `make_pack.py` add their entry automatically; news/fact posts are added with `update_site.py post <post.json> [card.png]`; `update_site.py link latest <x_url>` sets the X link after posting; `tools/scrape_x.js` (run on the X profile) + `update_site.py sync <file>` adds any posts that are missing (news, facts, manual posts). The app's Posts tab and chat read it. Every scheduled posting task must log its post here.
- `app-beta/` — UNLISTED test build of the AI Radar app (installable PWA, `noindex`, not linked from the site). Four tabs: Chat, Explore, Posts, Saved. Explore (`#explore`, `#glossary`) has two sections: Resources — with no search it browses AI Radar's own items; a search (or an "I want to…" tile, via `TASK_Q`) runs a global search live from the browser (`runWeb`, cached per query, 450 ms debounce): AI Radar picks + GitHub repos (stars), Hugging Face models (downloads), apps/Spaces (likes), datasets (downloads), papers (`/api/papers/search`, upvotes) and Hacker News articles (points, last 2 years); view chips All / AI Radar / Repos / Models / Apps / Datasets / Papers / Articles with counts, sort Best match / Most popular (popularity ranked within each source so stars and downloads mix fairly) / Newest / A–Z, Free only (hides articles), topic chips; level filter only for AI Radar items. Browse mode uses (every repo, cheatsheet and prompt pack from the same `loadIndex()` the chat uses; tags from `TOPICS`, "I want to…" tasks from `TASKS` and level from `levelOf()`, all worked out in `app.js`; type / Free only / level / topic filters, sort, Save, Ask about this) and Glossary (`app-beta/glossary.json`: `term`, `def`, `tag`; search, Ask, "<tag> resources" jumps to Resources filtered by that topic, Save as a Note). Chat works like an AI search engine (`gatherSources` → `ai(history, sources)` → `answerV2`): for every AI question the app first collects up to 10 sources (12 for repo questions), AI Radar resources and posts first, then Wikipedia, GitHub, Hugging Face models/apps/datasets/papers and Hacker News, each capped at 7 s; sends them numbered to the Worker, which writes one answer citing them as [n] (news headlines it finds are numbered after them) and returns 3 `related` questions; the app shows a Sources strip, the answer with tappable [n] links (`citeHTML`), an "All sources · save any" list, Related questions and "See all results in Explore". Off-topic questions get the Worker's polite no with no sources. Saved chats from before keep their old layout (`data.v` is 2 for the new one). An older Worker without source citing still answers; the strip shows without [n] links. Chat (the Worker call `ai()` waits up to 45 s, retries once (35 s) on a slow model, a dropped connection or a bad reply, then shows an honest error with a Retry button (`data-retry`); the Worker itself gives OpenRouter 35 s and answers 504 "taking too long"; source cards: AI Radar resources and posts first, then GitHub for repo questions, otherwise Hacker News + Wikipedia + the Worker's answer; recommendation questions (`BEST_Q`: best, top, recommend, which tool, alternatives to…) first try the Worker's "Best for you" (`bestCall`, progress stages while it works, numbered picks with Why / Trade-off / Start, Save, refine chips that re-ask, More options) and fall back to the normal answer if the Worker has no `best` action; Explore shows a "Find the best for me" button above global results that runs the same search (`runBest`, cached per query); every topical answer also gets an "Across AI" group from the same global sources as Explore (`chatGlobal`: top 2 GitHub repos unless it is already a repo question, 2 Hugging Face models, 2 apps, 2 papers, 1 dataset, 11 s cap) and a "See all results in Explore" button; "show our posts about agents" searches the archive; "what did I save about RAG last year?" searches Saved), Posts (every post from `data/posts.json` with type/date/topic/search filters and a save button), Saved (on-device, localStorage `airadar-library-v1`; custom topics in `airadar-topics-v1`; collections in `airadar-collections-v1`, each item lists its collections in `cols`; a collection filter row on top, "Collections" on each item opens a picker with a new-collection field, "Share collection" makes a link `app-beta/#col=<base64url JSON>` carrying the items themselves (no upload; opening it asks to import), "Ask about this" on each item asks the chat): filters for type, date, topics (multi-select, all must match), site and search (title, description, note), each with counts; sort newest/oldest/A–Z; per item Open / Edit / Copy link / Share / Delete; Export/Import as a JSON file. A floating liquid-glass + button on every tab opens the "Add to Saved" sheet (link, title, note, type, topics): pasting a link auto-fills from the GitHub API (repos), the Hugging Face API (models, spaces, datasets), noembed.com (videos), otherwise the Worker's `{action:'preview'}` page preview, falling back to a title from the URL; topics come from `TOPICS` in `app.js` (Local LLMs, Agents, MCP, RAG, Coding, Image, Video, Audio & Voice, Prompts, Spreadsheets, Fine-tuning, Datasets, Security, Learning, Careers, LLMs, Research) plus custom ones. The same link saved twice is updated (matched by `normUrl`). The manifest `share_target` (GET `./?title&text&url`) opens the sheet from Android's share menu. The tab bar has a sliding clear glass lens (`#tab-pill`, white highlights only, with a mint glow `#tab-glow` shining up from under it; the + button uses the same clear glass + under-glow look; driven in `app.js`): it springs to the selected tab with a squash-and-stretch, magnifies the icon under it, can be dragged across the tabs (release picks the tab), lifts while pressed and leans toward the hovered tab on desktop; instant under reduced motion. The top bar, chat box and tab bar float over the content and are liquid glass from `@samasante/liquid-glass` (React), bundled with React into `app-beta/vendor/glass.js` (committed). To change it: edit `app-src/glass-entry.jsx`, then `cd app-src && pnpm install && pnpm build` and bump `vendor/glass.js?v=N` in `app-beta/index.html` and `sw.js`. Without the bundle the bars fall back to a CSS blur. Service worker `sw.js`, `manifest.webmanifest`, icons in `app-beta/icons/`. Promote to `app/` once approved.
- `app-smart/` — UNLISTED web version of the Android app (same screens as `app-beta/`, `noindex`, not linked from the site). Its chat goes to the app's own smart-bot Worker `airadar-app-bot` (`https://airadar-app-bot.arinsingh2304.workers.dev`; its code lives in the Android project, not this repo), set in `app-smart/config.js`. That Worker accepts this page by its `https://airadar08.github.io` origin, so no key is in the page. Every question goes to the bot (web, news, GitHub, Hugging Face tools); `app.js` differs from `app-beta/app.js` there. No service worker or manifest. Bump the `?v=N` on its scripts in `app-smart/index.html` when changing them.
- `.nojekyll` — keeps GitHub Pages from running Jekyll.

## Brand
- Theme: dark everywhere (no light mode). Ground `#0a0c0b`, cards `#111412`, lines `#1f2521`, text `#eef1ee`, muted `#9aa39c`, mint accent `#34c98a` (soft `#12271e`, light `#6fdcaa`). Primary buttons are mint with near-black text. Home hero and CTA are a dark radar (grid, rings, slow sweep) echoing the X banner.
- Fonts (Google Fonts): Instrument Serif (weight 400) for headings, Inter for body and the "AI Radar" name, JetBrains Mono for small labels.
- Logo: `assets/logo.svg`, the same mark as the X profile picture. No company logos or trademarks.
- Post card images keep their own designs. Post cards: cheatsheets use the fixed cream/mint "Resources" theme; repos use the fixed dark theme; news/updates/facts keep the 8 rotating slot colours.
- Motion: subtle (fade/rise, hover lift, the radar sweep). Always respect `prefers-reduced-motion`.

## Adding a new prompt pack
Write a pack JSON (see `tools/make_pack.py` docstring) and run `python3 tools/make_pack.py pack.json [x_post_url]`, then commit and push. The X post uses `prompt-packs/<slug>/cover.baked.html`; commenters get `https://airadar08.github.io/prompt-packs/<slug>/`.

## Adding a new repo
Run `python3 tools/update_site.py repo <card.jpg> <repo.json> [x_post_url]`, then commit and push.

## Adding a new cheatsheet
Prefer `python3 tools/update_site.py cheatsheet <slug> <card.jpg> "<title>" "<subtitle>" "<tag>"`. Manually:
Add the 1080x1350 image as `cheatsheets/img/<slug>.jpg`. Insert the new `<article class="sheet reveal" id="<slug>">` right after the `<!-- new-cheatsheet:page -->` marker in `cheatsheets/index.html` (newest first); insert a matching `<a class="res reveal">` card right after `<!-- new-cheatsheet:home -->` in `index.html`. Copy the markup of the existing entries exactly.

## Adding a new free resource
1. Create `<slug>/index.html` using the same head, header and footer as `cheatsheets/index.html` (links `../assets/site.css`), page-specific CSS inline, works at 400px width.
2. Add a card for it in the "Free resources" list in `index.html`, above the "More coming soon" card.
3. Commit and push to `main`, then check `https://airadar08.github.io/<slug>/` loads.
4. The resource link used in X replies is `https://airadar08.github.io/<slug>/`.

## Rules
- The site itself stays static (no trackers, no forms that submit anywhere). The only backend is the chat Worker.
- Never put an API key or secret in any file in this repo.
- Plain, direct copy; real content only.

- Never show posting frequency or schedules (posts per day, times) anywhere on the site.
- When changing anything in `assets/`, bump the `?v=N` on its links in every page (home, repos, cheatsheets, prompts, prompt-packs, tools/pack_template.html) so browsers fetch the new file.

## Every post on X must land on this site (standing rule)
After ANY post on @ai_radar_ (news, AI fact, repo, cheatsheet, prompt pack, small packs, hand-made posts):
1. Run tools/scrape_x.js on https://x.com/ai_radar_ (browser), save the string to /tmp/x_posts.json.
2. `python3 tools/update_site.py sync /tmp/x_posts.json` (adds new posts to data/posts.json, fills X links).
3. Short prompt packs ("Prompt pack: 3 prompts ...") also get their own page: write a pack.json and run
   `python3 tools/make_pack.py pack.json <x_url>`, then commit and push to main.

## Prompt packs: always the green + black house style
Every prompt pack (any size, even 3 prompts) is made with `python3 tools/make_pack.py pack.json [x_url]`.
Its cover (cream page, green headline, black "Follow + comment" bar, `cover.baked.html`) is the ONLY image used for the X post
and the site. Never use the rotating-colour "AI Radar Notes" card (render_card.py) for a prompt pack.
Post the pack's `cover.baked.html`, link/page = prompt-packs/<slug>/, then sync the archive.
